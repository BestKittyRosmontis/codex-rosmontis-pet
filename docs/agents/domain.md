# Domain docs

This is a single-context application. Domain terms belong in root `GLOSSARY.md`; architectural decisions belong in `docs/adr/`. Vendored dependencies do not form separate project contexts.

Before investigating a feature, read the glossary if it exists and the ADRs relevant to that feature. If either is absent, continue without creating placeholder terms or decisions. Use established glossary terms and identify conflicts with an existing ADR when proposing changes.
